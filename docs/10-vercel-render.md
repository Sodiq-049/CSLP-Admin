# 10 · Deploying on Vercel + Render

The admin portal (frontend) runs on **Vercel**; the API and the background worker (backend) run on **Render**. The database stays on **MongoDB Atlas**. General production guidance is in [09-deployment.md](09-deployment.md).

```
 Browser ─▶ Vercel: cslp-admin (Next.js)
              │  /api/* rewritten (streamed) to the API, so cookies stay on the admin domain
              ▼
            Render: cslp-api (web service) ─┬─▶ MongoDB Atlas
            Render: cslp-worker (worker)  ──┼─▶ Render Key Value (job queue, private)
                                             ├─▶ Cloudflare R2 bucket (files, S3-compatible)
                                             └─▶ OpenAI · SMTP provider
```

| Piece        | Where                                        | Config file                                           |
| ------------ | -------------------------------------------- | ----------------------------------------------------- |
| Admin portal | Vercel project, root `apps/admin`            | [`apps/admin/vercel.json`](../apps/admin/vercel.json) |
| API          | Render web service `cslp-api`                | [`render.yaml`](../render.yaml)                       |
| Worker       | Render background worker `cslp-worker`       | `render.yaml`                                         |
| Queue        | Render Key Value `cslp-queue`                | `render.yaml`                                         |
| Files        | Cloudflare R2 (Render has no object storage) | set in Render env vars                                |
| Database     | MongoDB Atlas (your cluster)                 | `MONGODB_URI`                                         |

Region: Render **Frankfurt** (closest Render region to Lagos). For speed, keep the Atlas cluster in a Frankfurt region too (e.g. AWS `eu-central-1`).

## 1. Prepare (once)

1. **Push the repository to GitHub** (Vercel and Render both deploy from it).
2. **Files bucket — Cloudflare R2:** Cloudflare dashboard → R2 → _Create bucket_ (e.g. `cslp-files`, private). Then _Manage R2 API tokens_ → create a token with _Object Read & Write_ on that bucket. Note the **Access Key ID**, **Secret Access Key** and the S3 endpoint `https://<account-id>.r2.cloudflarestorage.com`.
3. **Email (Resend):** Domains → add your domain and its DNS records (SPF/DKIM) until it shows *Verified*; API Keys → create a key with *Sending access*. The blueprint already sets `SMTP_HOST=smtp.resend.com`, `SMTP_PORT=587`, `SMTP_USER=resend`. You supply only `SMTP_PASS` (the API key) and `MAIL_FROM` (e.g. `CSLP <no-reply@yourdomain.ng>`).
4. **Atlas connection string** ending in `/cslp`, e.g. `mongodb+srv://USER:PASS@cluster0.xxxx.mongodb.net/cslp?retryWrites=true&w=majority`.

## 2. Backend on Render

1. Render dashboard → **New → Blueprint** → choose your GitHub repo. Render reads `render.yaml` and proposes `cslp-api`, `cslp-worker`, `cslp-queue` and the env group `cslp-shared`.
2. Fill in the values it asks for:
   - `MONGODB_URI`, `OPENAI_API_KEY`
   - `S3_ENDPOINT`, `S3_BUCKET`, `S3_ACCESS_KEY_ID`, `S3_SECRET_ACCESS_KEY` (from R2)
   - `SMTP_PASS` (Resend API key), `MAIL_FROM`
   - `ADMIN_APP_URL`: put `https://cslp-admin.vercel.app` for now; correct it after step 3 if Vercel gives a different URL
   - `SEED_SUPER_ADMIN_EMAIL`: your email
     `JWT_ACCESS_SECRET` and `MFA_ENCRYPTION_KEY` are generated by Render — leave them.
3. **Apply.** The first build takes ~5 minutes. Then open `https://cslp-api.onrender.com/api/v1/public/health` (your service URL may differ) — it should say `"status":"ok"`.
4. **Atlas network access:** Render → `cslp-api` → _Connect_ → _Outbound_ shows the service's outbound IP ranges. Add each one in Atlas → _Network Access_. (The worker shares the same region ranges.)
5. **Admin account:** your Atlas `cslp` database already has your super admin, so nothing to do. For a brand-new database, open `cslp-api` → _Shell_ and run `SEED_SUPER_ADMIN_PASSWORD='your-password' node apps/api/dist/scripts/seed.js`.

## 3. Frontend on Vercel

1. Vercel dashboard → **Add New → Project** → import the same GitHub repo.
2. **Root Directory:** `apps/admin` (Vercel picks up `apps/admin/vercel.json` and pnpm automatically). Framework: Next.js.
3. **Environment variables** (Production, and Preview if you use it):
   | Name             | Value                                                     |
   | ---------------- | --------------------------------------------------------- |
   | `API_URL`        | your Render API URL, e.g. `https://cslp-api.onrender.com` |
   | `API_PROXY_MODE` | `rewrite`                                                 |
4. **Deploy.** Open the Vercel URL → sign in with your email and password.
5. If the Vercel URL isn't `https://cslp-admin.vercel.app`, set `ADMIN_APP_URL` on Render's `cslp-api` to the real one (it's used in email links) — Render redeploys automatically.

Why `API_PROXY_MODE=rewrite`: Vercel serverless functions only accept 4.5 MB request bodies. In rewrite mode Vercel streams `/api/*` straight to Render, so outline and source uploads up to 50 MB work, and sign-in cookies stay on the Vercel domain. `API_URL` is read at build time in this mode — **redeploy Vercel after changing it**.

## 4. Updates

Push to the main branch: Render rebuilds the API and worker, Vercel rebuilds the portal. Both keep previous deploys for one-click rollback (Render → _Events_ → _Rollback_; Vercel → _Deployments_ → _Promote_).

## 5. Custom domains (optional)

- Vercel → Project → _Domains_ → `admin.yourdomain.ng`; Render → `cslp-api` → _Custom Domains_ → `api.yourdomain.ng`.
- Then update `ADMIN_APP_URL` (Render) and `API_URL` (Vercel, then redeploy). Later, add the student website's origin to `CORS_ORIGINS` and set `STUDENT_APP_URL`.

## 6. Checks after the first deploy

- **Visitor IPs:** Settings → _Active sessions_ in the portal should show your real IP. `TRUST_PROXY_HOPS=2` matches Render's proxy plus Vercel's. If you see a Vercel/Cloudflare address instead, adjust it (it controls sign-in rate limits and audit IPs).
- **Uploads:** upload a PDF in _Source Library_; it should reach _Ready_ (that proves API → R2 → worker → Atlas).
- **Email:** _Forgot your password?_ on the sign-in page should deliver a link.

| Item                           | Price            |
| ------------------------------ | ---------------- |
| Render `cslp-api` (0.5c-512mb) | US$7             |
| Render `cslp-worker` (0.5c-512mb) | US$7             |
| Render Key Value (256mb)    | US$10            |
| Vercel (Hobby / Pro)           | US$0 / US$20     |
| Cloudflare R2                  | free up to 10 GB |
| Atlas, OpenAI, SMTP            | your plans       |

Render's free web plan sleeps after inactivity (slow first request, and the worker type has no free plan), so the smallest paid plan is recommended for the API. Vercel's Hobby plan is for non-commercial use; use Pro for an institution.
